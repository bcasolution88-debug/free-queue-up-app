# 移动端排队取号平台 APP 项目架构设计

## 1. 项目概述

本项目是一个基于移动端的排队取号平台 APP，旨在解决实体店排队耗时的问题，提供在线下单、排队、通知领取等全流程服务。项目涵盖用户端、商家端和管理员后台，采用前后端分离架构，前端基于 Uni-app (Vue 3 + JS) 开发，后端基于 uniCloud (云函数 + 云数据库) 实现。

## 2. 核心功能模块

### 2.1 用户端
- **首页**：展示商家列表、支持搜索，实时显示各商家的在线和实体店排队人数。
- **商家详情与下单**：展示商家产品，支持选择产品和领取时段，加入购物车并结算。
- **排队状态**：实时显示当前排队号码、预估等待时间、前面排队人数。
- **支付与退款**：支持在线支付，提供未领取退款机制和爽约赔款机制。
- **个人中心**：订单管理、语言切换（中英双语）、主题切换（白天/夜间模式）。

### 2.2 商家端
- **订单管理**：查看和处理用户订单。
- **排队管理**：管理在线队列和实体店队列，手动叫号或自动叫号。
- **通知用户**：商品准备就绪后，一键通知用户到店领取。

### 2.3 管理员后台
- **商家与产品管理**：增删改查商家信息和产品信息。
- **数据统计**：查看全平台订单、排队等统计数据。

## 3. 技术栈选择

- **前端框架**：Uni-app (Vue 3 Composition API)
- **UI 组件库**：uView UI (或 uni-ui) - 适合卡片式设计和现代流行风格
- **状态管理**：Pinia
- **多语言**：vue-i18n (支持中英双语，持久化存储)
- **后端服务**：uniCloud (阿里云/腾讯云空间)
  - **云函数**：处理业务逻辑（下单、排队分配、支付回调等）
  - **云数据库**：JQL 语法，存储用户、商家、订单、队列数据
- **实时通信**：uniCloud 数据库监听 (watch) 或 uniPush 推送

## 4. 数据库设计 (uniCloud DB Schema)

### 4.1 Users (用户表)
- `_id`: 用户ID
- `openid`: 微信/支付宝 openid
- `nickname`: 昵称
- `avatar`: 头像
- `role`: 角色 (user/shop_admin/super_admin)
- `lang_preference`: 语言偏好 (zh/en)

### 4.2 Shops (商家表)
- `_id`: 商家ID
- `name`: 商家名称
- `logo`: 商家Logo
- `address`: 地址
- `location`: 地理位置 (GeoPoint)
- `status`: 营业状态

### 4.3 Products (产品表)
- `_id`: 产品ID
- `shop_id`: 关联商家ID
- `name`: 产品名称
- `price`: 价格
- `image`: 产品图片
- `inventory`: 库存数量

### 4.4 Orders (订单表)
- `_id`: 订单ID
- `user_id`: 用户ID
- `shop_id`: 商家ID
- `items`: 购买产品列表
- `total_amount`: 总金额
- `status`: 状态 (pending/paid/ready/completed/cancelled/refunded)
- `pickup_time`: 预约领取时段
- `queue_no`: 排队号码
- `queue_type`: 排队类型 (online/instore)
- `created_at`: 创建时间

### 4.5 Queues (队列实时状态表)
- `shop_id`: 商家ID
- `online_queue_count`: 在线排队人数
- `instore_queue_count`: 实体店排队人数
- `current_calling_no`: 当前叫号
- `estimated_wait_time_per_person`: 预估单人等待时间(分钟)

## 5. 关键业务流程

### 5.1 下单与排队流程
1. 用户浏览商家和产品，选择领取时段。
2. 提交订单并完成在线支付。
3. 后端云函数验证库存，生成订单，并分配排队号码（按时间排序）。
4. 订单状态更新为已支付，进入排队队列。
5. 前端通过数据库监听实时更新排队进度和预估时间。

### 5.2 领取与通知流程
1. 商家在后台看到新订单，准备商品。
2. 商品准备完毕，商家点击"通知领取"。
3. 订单状态更新为"待领取"，触发 uniPush 推送通知给用户。
4. 用户到店出示号码，商家确认核销，订单完成。

### 5.3 退款与爽约机制
- **未领取退款**：超过预约时间一定时长（如2小时）未领取，系统自动取消订单并按比例退款。
- **爽约赔款**：如果用户频繁爽约，可在退款时扣除一定比例的爽约金，具体规则在云函数中配置。

## 6. UI 设计规范

- **风格**：现代卡片式、圆角、阴影，参考美团、饿了么。
- **色彩**：
  - 主题色：#FF4D4F (活力红)
  - 白天模式：背景 #F5F5F5，卡片 #FFFFFF，主文本 #333333
  - 夜间模式：背景 #121212，卡片 #1E1E1E，主文本 #E0E0E0
- **布局**：底部 TabBar 导航，顶部 NavBar (含语言和主题切换)。

4. 商家端与管理员端开发
5. UI 设计图生成
6. 源码打包与交付

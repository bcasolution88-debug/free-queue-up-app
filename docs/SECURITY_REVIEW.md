## 未在本次修复的业务安全限制

此次仅处理仓库导入与泄露检查，不扩展认证或支付开发：

- 普通登录、注册、社交及快速登录均为模拟流程；管理员入口不是可靠权限控制。
- 创建订单直接采用请求 userId；商家操作未将调用者与可信商家身份绑定。
- 支付回调缺少完整支付方验签；退款与爽约处理缺少完整权限控制，且包含模拟处理。
- 库存扣减、编号分配、服务端计价、事务、幂等性及防重仍需完善。

这些问题不属于凭据泄露，但足以阻止生产上线。禁止向演示页面输入真实密码，禁止直接开放这些云函数用于生产写入或真实收付款。

## 复查方式

安装 Gitleaks 后，可在项目根目录执行：

```bash
gitleaks dir . --redact=100 --no-banner
gitleaks git . --redact=100 --no-banner
```

第一条检查当前目录，第二条检查本地 Git 历史。任何真实秘密一旦进入历史，即使随后删除也应轮换，不应仅靠 `.gitignore` 隐藏。

项目当前没有测试或 lint 脚本。本次不安装业务依赖、不执行 Uni-app 构建或云端部署，不能把静态扫描通过解释为应用功能测试通过。
